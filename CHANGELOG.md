# Changelog

All notable changes to BindingMetrics are recorded here, in the format of [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Issue numbers refer to the GitHub issue tracker of the project. Example values come from the structures in `data/`: 1YCR (p53 peptide with MDM2), 3P8F (SFTI-1 with matriptase), 1CWA (cyclosporin A with cyclophilin A), 1XY4 (somatostatin analogue), 3V3B (stapled peptide) and 1QJB (phosphopeptide).

## [Unreleased]

## [0.2.0] - 2026-10-14

0.2.0 adds:

- the pose-set layer: `binding_metrics.poses` and `score_pose_set`, with `Reference`, frame placement, pose agreement, aggregation, descriptors, cross-model reconciliation and `write_pose_report`;
- the prediction layer: adapters (`of3`, `af2`, `boltz2`, `protenix`), runners for OpenFold3, Boltz-2, Protenix and ColabFold behind a run-once store (`PredictionStore`, `PredictionSession`), and `--predictor` on `binding-metrics-run` and `-batch`;
- pre-flight capability checks (`binding_metrics.capabilities`), the modes `predict`, `refold`, `score`, `score-lock` and `refold-lock`, and an MSA policy that forbids the server;
- residue numbers, insertion codes and author chain IDs kept through preparation, relaxation and `save_cif`;
- test tiers (`pytest`, `--full`, `--gpu`) and code-area markers.

OpenFold3 0.5.0 (1YCR, 1CWA, 3P8F) and Boltz-2 2.2.1 (1YCR, 1CWA, 3P8F, 1XY4) were run for real; Protenix and ColabFold only against a stand-in process. Corrections to the metrics change reported values, listed under "Changed results".

### Added

**Prediction readers**

- `binding_metrics.predictors`: `PredictedPose`, `PredictionFiles`, `TokenLayout` and `SampleRef` (pLDDT per atom on 0-100, PAE and PDE in angstrom with the row as alignment frame, NaN for a missing value, `chain_map`, `PredictedPose.validate()`). `PredictionParser` (`find_files`, `parse`, `load`, `list_samples`, `complete(record)`, `not_provided`) is the base class of an adapter, registered with `ParserSpec`, `PARSERS`, `get_parser` and `register_parser`; an adapter reads output files and never runs a model. `not_provided` names the fields a model never writes (AlphaFold2: `pde`, `gpde`, `disorder`, `has_clash`).

Lazy exports: `compute_prediction_metrics` of `binding_metrics` and `binding_metrics.metrics`; `PredictionRequest`, `StoredPrediction`, `PredictionStore`, `PredictionFailedError`, `PredictionUnavailableError`, `PredictionSession`, `PredictionRunner` and `OpenFold3Runner` of `binding_metrics.predictors`.

Layout read: `<pred>/<name>/seed_<S>/<name>_seed_<S>_sample_<k>_{model.cif,confidences.json,confidences_aggregated.json}`, `timing.json`; `experiment_config.json`, `summary.txt`, `runner_config.yaml`, `inference_query_set.json`, `model_config.json`, `msas/` in `<pred>/`. `OpenFold3Parser.complete` builds `record.tokens` with `binding_metrics.predictors.of3.token_layout(record)` and `STANDARD_RESIDUE_NAMES` (one token per standard residue, one per heavy atom otherwise), so the interface PAE and PDE blocks are cut at chain boundaries; `record.tokens` stays None with a `reason` when the layout does not fit. `list_samples` reads only the aggregated confidence files (#146).
- `af2` adapter (`get_parser("af2")`): ColabFold jobs (`{job}_scores_rank_*.json`, `{job}_unrelaxed|relaxed_rank_*.pdb`), AlphaFold2 v2.3.2 directories (`result_*_pred_*.pkl`, `ranking_debug.json`, `timings.json`, `confidence_*.json`, `pae_*.json`) or a structure alone. The pLDDT per residue is repeated over its atoms; `pae[i, j]` is the error of residue j aligned on residue i; `gpde`, `disorder`, `has_clash` and PDE are not provided. Read from the ColabFold 1.6.3, 1.5.4 and AlphaFold2 v2.3.2 source; no model run. `read_bfactor_plddt` and `load_bfactor_record` (`binding_metrics.predictors.af2`) read pLDDT from the B-factor column of a bare AlphaFold2 or BindCraft structure; `read_result_pickle` refuses every global but numpy arrays, numpy scalars and dictionaries.
- `boltz2` adapter (`get_parser("boltz2")`): `boltz_results_*/predictions/{name}/` with `{name}_model_{r}.cif|pdb`, `confidence_{name}_model_{r}.json`, `plddt_`, `pae_` and `pde_` `.npz`; `sample=1` is the best-ranked model (`r = 0`). pLDDT 0-1 -> 0-100, expanded from token to atoms, with the matching `TokenLayout`; `chain_pair_iptm` key `"A-B"` is chain A scored, alignment on chain B; `iptm` of a single chain is NaN; `ligand_iptm`, `protein_iptm`, `complex_iplddt` and `complex_ipde` go to `record.extras`; `has_clash` and `disorder` are NaN. Read from the Boltz v2.2.1 source.
- `protenix` adapter (`get_parser("protenix")`): the summary and full-data JSON of a sample (the latter only with `--need_atom_confidence true`; without it the record keeps the scalars and `reason` names the flag). pLDDT 0-1 -> 0-100; chain lists keyed by position (`"0"`, `"0-1"`) until `ProtenixParser.complete`, which re-keys them by chain ID and builds the `TokenLayout` with `binding_metrics.predictors.protenix.token_layout(record)`; without a layout the blocks are cut by residue. `disorder` is NaN (Protenix writes 0). - `compute_evobind_adversarial_from_records` (`binding_metrics.metrics.evobind`): the adversarial check between two `PredictedPose` objects, chain IDs after each `chain_map`, `design` also a path; the keys of `compute_evobind_adversarial_check` plus `design_model` and `adversary_model`, and the geometric keys with a `reason` when the second prediction has no per-atom pLDDT. `compute_evobind_score_from_record`: `compute_evobind_score` plus `model`. `receptor_interface_residues` of both score functions accepts residue numbers (52 selects 52 and 52A), labels (`"52A"`) and `(number, insertion code)` pairs (#124); another kind raises `ValueError`. - `binding_metrics.metrics.mlff_energy`, a reserved interface for an interaction energy from a machine-learned force field (Ryczko et al., ChemRxiv 10.26434/chemrxiv.15008810): `MLFFBackend`, `PocketSpec`, `register_backend`, `get_backend`, `available_backends`, `compute_mlff_interaction_energy` (validates its arguments, raises `NotImplementedError`). Not a registered metric.

**Prediction runners and store**

- `binding_metrics.predictors.store`: `PredictionRequest` holds everything that changes a prediction (model and version, mode, seeds, samples, options, chain roles, content hash of the input file, never its path); `key()` is a SHA-256 of it. `PredictionStore(root)` keeps one directory per key (`request.json`, `STATUS.json`, `outputs/`) with `lookup`, `get_or_run`, `adopt` and `run_missing` (one batched call), written to a temporary directory and renamed under an `fcntl` lock per key. A failed run is recorded and not retried unless `rerun=True`; a model that cannot start raises `PredictionUnavailableError` and records nothing.
- `PredictionSession(store, runners, parsers)` (`binding_metrics.predictors.session`): `record(request)` runs the model on the first miss only and parses once; `records(request, *, chain_map=None)`, `lookup(request)`, `prefetch(requests)`, `adopt(request, directory)`, `stats()` (requests, memo hits, store hits, adopted outputs, misses, runs, failures, parses). `record` writes `backend`, `mode`, `receptor_forced`, `receptor_templated`, `seed`, `seed_index`, `sample`, `request_key`, `model_version`, `request_name` and, when the request names an MSA, `msa_policy`, `msa_receptor`, `msa_binder` into the pose `provenance` (`seed` None with a reason when no source gives it). `receptor_forced(request)` and `receptor_templated(request)` (`binding_metrics.predictors`) derive the first two. `prediction_manifest(session, requests)` (`binding_metrics.predictors.manifest.manifest`) lists one JSON-ready row per `(backend, seed, sample)` and one per request that failed or has nothing stored; it never starts a model.
- `PredictionRunner` (`binding_metrics.predictors.runners`), the base class of a model runner: `prepare`, `run`, `supports_batch`, `run_many`, `is_available`, `version`, `supported_modes` (`{"predict"}`; `run_modes` is read when a runner names the modes it builds an input for), `default_mode`, `output_chain_map(request)` (None), `supports_given_msa`, `supports_single`, `supports_custom_weights` (False), `weights_kind` (`"file"` or `"directory"`), `check_weights`, `seed_dimension` (False). `make_requests(input_path, *, seeds, **options)` builds one request per seed (`<name>_s<seed>`), or one with all seeds when `seed_dimension` is True (`OpenFold3Runner`, `ProtenixRunner`); `_group_seeds(seeds)` is the hook for a runner that takes only some seed lists; duplicate, negative and empty lists raise `ValueError`. ColabFold records report `extras["seed_value"]`.
- `OpenFold3Runner` (`binding_metrics.predictors.of3_runner`) starts OpenFold3 through `run_openfold_scoring`, `run_openfold_refolding`, `run_openfold_batched` and `run_openfold`; `make_request` puts every setting that changes the output, the user-default `runner.yml` included, into the request; `weights=` takes a checkpoint file.
- `ColabFoldRunner` (`binding_metrics.predictors.af2_runner`) starts AlphaFold2 and AlphaFold-Multimer through `colabfold_batch`: one FASTA record per request, receptor then binder joined by `:` (chain A receptor, B binder); mode `predict` only; `use_msa_server=False` writes `--msa-mode single_sequence`; seeds are consecutive integers from 0 (`--random-seed`, `--num-seeds`), `num_samples` is `--num-models`; custom parameters are `weights`, a `--data` directory identified by content. Residues AlphaFold2 cannot take (D-amino acid, N-methylated, phosphorylated or other CCD components, selenocysteine) are refused before anything is written; non-integer seeds raise `ValueError` (#151). Tested with a stand-in process; not run against ColabFold.
- `ProtenixRunner` (`binding_metrics.predictors.protenix_runner`) starts `protenix pred`: input JSON from the two chains (receptor entity 1, binder entity 2, modified residues as `CCD_<code>`); mode `predict` only; always `--need_atom_confidence true`; the request holds model name, dtype, seeds (`[101]`), samples, `use_msa_server`, `msa_server_mode`, `constraints`, `covalent_bonds`, the closure setting, `extra_args` and the size of the default weights file. A head-to-tail or disulfide binder gets `covalent_bonds` (`binder_cyclic="auto"`). Custom weights: a directory with `<model_name>.pt`, passed through a temporary `PROTENIX_ROOT_DIR`. Read from Protenix 2.0.0 (commit 85767b8); tested with a stand-in process; not run against Protenix.
- `Boltz2Runner` (`binding_metrics.predictors.boltz2_runner`) starts `boltz predict` in the current environment or through `conda run -n ENV`: one protein entity per chain under the chain IDs of the input, modified residues as CCD codes in `modifications`, `cyclic: true` for a head-to-tail binder (`binder_cyclic="auto"`), `msa: "empty"` without the MSA server. Modes `predict`, `refold` (receptor templated from a CIF of the input), `score` (each chain templated from its own CIF), `score-lock` (one CIF of both chains in the input frame, `force: true` and a threshold) and `refold-lock` (the receptor chain alone), all in `RUN_MODES`. `lock_threshold_angstrom` defaults to 2.0 A (Boltz-2 documents none) and is in the key; one seed (default 42), `num_samples` (default 5), custom weights as `--checkpoint`. Failures raise `Boltz2RunError` (a `CalledProcessError`), `RuntimeError` (exit 0 without output) or `ValueError` (a residue Boltz-2 cannot express). Run for real on Boltz-2 v2.2.1 (single-sequence mode, `--no_kernels`); not run: `use_msa_server=True`, a conda environment.
- `Boltz2Runner.make_request(..., closure_bonds="none" | "auto" | list)` writes Boltz-2 `bond` constraints: `"auto"` takes the head-to-tail amide, disulfide and lactam links of `detect_closures` (a staple or other cross-link logs a warning); a list of `{"atom1": [chain, position, atom], "atom2": [...]}` is written as given after a check. Default `"none"` keeps the YAML and the key. Run on 3P8F, 1CWA, 1XY4 and two made-up sequences; ligands, nucleic acids and chains of three or more were not run. `write_embeddings=True` passes `--write_embeddings`; `Boltz2Parser` registers `embeddings_<name>.npz` as `PredictionFiles.extra["embeddings"]`, with `extras["embeddings_path"]`, `provenance["embeddings_path"]` and the manifest column `embeddings_path`. `predictors/_closures.py` places a closure in the sequence for the Protenix and Boltz-2 runners.
- `template_mode` (`"structure"`, the default, or `"alignment"`) on `prepare_scoring_query`, `prepare_refolding_query`, the two batched `prepare_*` functions, `run_openfold_scoring`, `run_openfold_refolding`, `run_openfold_batched` and `OpenFold3Runner.make_request` (in the key), and `--openfold-templates {structure,alignment}` on `binding-metrics-run` and `-batch` (keyword `openfold_templates` of `run_pipeline` and `run_batch`) and on the query and run subcommands of `binding-metrics-openfold`. `structure` writes `template_cif_paths` (CIF Direct Template Mode, protein chains only) in place of an A3M alignment, which the ColabFold MSA server overwrites, and needs OpenFold3 0.4.2 or later (`ValueError` naming `--openfold-templates alignment`); `alignment` keeps the A3M marker `query-b<V>`. OpenFold3 only: no `--prediction-templates`, and `alignment` with another `--predictor` is a usage error.
- Template accounting for OpenFold3: after each run `inference_query_set.json` and the two loss messages (`UserWarning` on stderr, `Failed to preprocess template alignment` on stdout) are read; a warning names each chain that asked for a template and got none, with the cause (`replaced_by_msa_server`, `preprocessing_failed`, `no_template_kept`); `template_accounting.json` is written next to the output. `OpenFoldRunInfo.templates`, `results["prediction"]["templates"]` and `results["openfold"]["templates"]` hold `{chain: {requested, source, used, cause, detail, entry_ids}}`; CSV columns `prediction_templates_<chain>_*`; a "Templates" row in the report; `record.extras["templates"]`. `read_template_accounting(predictions_dir, query_name)` in `binding_metrics.metrics.openfold`. `OpenFold3Runner.run_many` copies both JSON files next to each split query.
- `on_unmappable_residue` (keyword-only, `"error"` by default, `"x"` sends an `X`) on `run_openfold_scoring`, `run_openfold_refolding` and `run_openfold_batched`; `UnmappableResidueError` importable from `binding_metrics.metrics.openfold`. `--on-unmappable-residue {error,x}` on `binding-metrics-run` and `-batch` (keyword `on_unmappable_residue` of `run_pipeline` and `run_batch`), as `binding-metrics-openfold` had; one such residue stops the single OpenFold3 call of a batch for every sample.
- `binder_cyclic` (`"auto"`, `True`, `False`) on `prepare_scoring_query`, `prepare_refolding_query`, the two batched `prepare_*` functions (which also take `conda_env`), `run_openfold_scoring`, `run_openfold_refolding`, `run_openfold_batched` and `OpenFold3Runner.make_request`; `decide_binder_cyclic` and `BinderCyclicDecision` (`cyclic`, `reason`). `auto` writes `"cyclic": true` for a head-to-tail binder of standard residues when OpenFold3 is 0.4.5 or later, otherwise no flag, with a warning and the reason in the result block; `True` raises `ValueError` for OpenFold3 older than 0.4.5. `--openfold-cyclic {auto,on,off}` (default `auto`) on `binding-metrics-run` and `-batch` (keyword `openfold_cyclic`) and on `prepare-query`, `prepare-scoring-query`, `score` and `refold` of `binding-metrics-openfold` (which also take `--conda-env` on the two prepare commands). The OpenFold3 block gets `binder_cyclic` (columns `openfold_binder_cyclic`, `prediction_binder_cyclic`; a summary row) and a `reason` when a head-to-tail binder was left linear (#77).
- Seeds (#67, #33): `seeds` on `run_openfold`; `--seeds` (alias `--openfold-seeds`) and `--num-seeds` on the `run`, `score` and `refold` subcommands of `binding-metrics-openfold` (`--num-seeds` is passed as `--num_model_seeds` only when given); `--openfold-seeds` on `binding-metrics-run` and `-batch`; the `seed_index` alias of `seed` in `compute_openfold_metrics`; `seed_value` in the dictionaries of `compute_openfold_metrics` and `summarize_prediction` (columns `openfold_seed_value`, `prediction_seed_value`). `--openfold-no-msa-server` on `binding-metrics-run` and `-batch` (keyword `openfold_use_msa_server=False`), for the `openfold` step and `--predictor of3`, in the key and in `provenance["openfold3_use_msa_server"]` (batch: `provenance_openfold3_use_msa_server`); `binding-metrics-openfold` had `--no-msa-server` (#68).

Options: `--prediction-dir DIR` reads an output you made (adopted into the store, the model never runs); `--prediction-binder-chain`, `--prediction-target-chain`; `--prediction-cache DIR` (default `<output-dir>/predictions`); `--rerun-predictions`. **Pre-flight**

- `binding_metrics.capabilities`, what a model or metric accepts and the input to check it against (#90). `Capabilities` is a frozen dataclass (binder types, ring closures, residue classes, binder size, single-chain binder, needs; every field defaults to "no constraint", and a constraint carries a sentence that says why). `profile_input(structure, binder_chain, receptor_chain=None, binder_type="auto")` returns an `InputProfile` (size and type of the binder; closures head-to-tail, disulfide, lactam, staple, other; residue classes canonical, D, N-methyl, phospho, other non-canonical, cap, ligand). `detect_closures` returns the links of `core.cyclic.detect_cyclization` on the six bundled examples without OpenMM; importing the module loads no OpenMM, torch or biotite. `preflight(profile, metrics, predictor=None, *, policy="error")` reads declarations only and collects every incompatibility with the fact found, the requirement, the reason and a fix: `error` raises `IncompatibleInputError` (a `ValueError`), `skip` leaves out the incompatible metrics, `warn` logs and runs everything. A step that declares no limit is never refused. See `docs/preflight.md`.
- `MetricSpec.capabilities`, an optional keyword-only `Capabilities` (#90). Receptor chain needed: `interface`, `coulomb`, `shape_complementarity`, `void_volume`, `delta_sasa_static`, `hbonds`, `saltbridges`, `evobind_score`, `evobind_adversarial`, `interface_pae`, `structure_interaction_energy`. Reference structure needed: `dockq`. Predicted structure needed: `evobind_score`, `evobind_adversarial`, `interface_pae`, `openfold`, `prediction`. Closures that `core.cyclic.patch_cyclic_topology` patches only (no thioether, macrolactone or biaryl ether): `md_implicit`, `structure_interaction_energy`.
- `Capabilities.extra_checks`, `check_openfold3_residues`, `InputProfile.residue_labels` and `InputProfile.other_protein_chains`: a limit can be a function of the profile, and any other protein chain meets a receptor need. The fix for a refused predictor lists the other registered predictors (declared compatible, no declared limits). `Capabilities`, `InputProfile`, `PreflightReport` and every `MetricSpec` can be pickled and deep-copied (#136).
- Declared limits of the adapters. `OpenFold3Parser.capabilities` (0.5.0): no ring closure but head-to-tail, and a residue check with the rule of the query builder, so a residue that `UnmappableResidueError` would refuse is refused before anything runs; a head-to-tail binder passes with a warning (#77). `ProtenixParser.capabilities`: no limit; a lactam, staple or other cross-link warns, a head-to-tail bond and a disulfide do not. `AlphaFold2Parser.capabilities`: no ring closure, the 20 amino acids only; capping groups and ligands warn. `Boltz2Parser.capabilities`: no limit; a hydrocarbon staple warns (the `bond` constraint is documented for canonical residues only).
- Pre-flight on the command line (#90): `binding-metrics-run` and `-batch` compare the input with the declared limits of every requested step and model before anything runs and refuse it with every problem at once. `--binder-type {auto,peptide,miniprotein,nanobody,antibody}` (default `auto`); `--on-incompatible {error,skip,warn}` (default `error`; `skip` leaves out the incompatible steps and records why, `warn` runs everything); `--preflight-only` (print the plan and stop, exit status 1 when something is refused). The decision is `results["preflight"]`, with the CSV columns `preflight_status`, `preflight_reason` and a block in the `--summary`; a refused batch sample is an `error` row that does not stop the batch; a prediction read with `--prediction-dir` only warns. `run_pipeline` and `run_batch` take `binder_type`, `on_incompatible` and `preflight_only`; `preflight` takes `predictor_policy`.
- Modes (#90): `binding_metrics.capabilities.MODES` are `predict` (sequences only), `refold` (receptor templated, binder free), `score` (every chain templated on its own, pose not given), `score-lock` (`score` with the pose pinned to the input) and `refold-lock` (`refold` with the receptor pinned by a forced template); `LOCK_MODES` names the last two. `Capabilities.modes` lists what a model supports and a caveat `modes:<mode>` warns: OpenFold3 0.5.0 `predict`, `refold`, `score`; Boltz-2 all five, warning for the lock modes (a guidance term); Protenix warns for `score-lock`; AlphaFold2 declares none. `preflight(..., mode=None, runnable=None)` refuses a mode a model does not list and names the models that declare it. `PredictionRequest.mode` accepts the five; the OpenFold3, Protenix and ColabFold runners refuse the lock modes. `--prediction-mode {predict,refold,score,score-lock,refold-lock}` on `binding-metrics-run` and `-batch` (needs `--predictor`; default `--openfold-mode` for `--predictor of3`; not checked for `--prediction-dir`), recorded as `mode` in `results["prediction"]` and `results["preflight"]` and as the column `prediction_mode`. `--prediction-lock-threshold` with another mode is a usage error (`ValueError` in `run_pipeline` and `run_batch`).
- MSA policy: `--prediction-msa-policy forbid-server`, with `--prediction-no-msa-server` and `--prediction-receptor-msa PATH` (or `single`), forbids any MSA server call; keywords `msa_policy` and `receptor_msa` of `make_request` of the four runners, `prediction_msa_policy` and `prediction_receptor_msa` of `run_pipeline` and `run_batch`. Pre-flight refuses a run that would use a server under every `--on-incompatible` value (`preflight(..., msa_policy="default", msa_server=None)`, violations of kind `msa`); the request refuses `use_msa_server=True` and a receptor without an MSA source; a runner checks the command line it built, `extra_args` included, for a server flag before it starts a process (`binding_metrics.predictors._msa`, `assert_no_server_flag`). The receptor MSA file is identified by content in the key; requests without these fields keep their keys. **Pose sets**

- `binding_metrics.poses`: `Pose`, the abstract base class, with the kinds `PredictedPose` (formerly `PredictionRecord`), `DockedPose` (its own `scores`, a `decoy` flag) and `ExperimentalPose` (`method`, `resolution_angstrom`, `pdb_id`, `quality`). Every pose has `kind`, `id`, `structure_path`, `atoms()` (chain IDs of `chain_map` applied, gzip read, cached), `chain_map`, `provenance` (JSON scalars), `content_hash()` (SHA-256 of the file bytes, or of a canonical serialisation of an in-memory `AtomArray` with coordinates rounded to 0.001 A) and `native_scores()`; a computed metric is never stored on a pose. `DockedPose` and `ExperimentalPose` are frozen dataclasses built with `from_file(path, *, ..., id=None, **provenance)` or `from_atoms`; a bare structure that is neither is a `DockedPose` with `decoy=True` and no `program`. Names load on first access. `PredictedPose.native_scores()` gives `avg_plddt`, `ptm`, `iptm`, `gpde`, `ranking_score`, `has_clash`, `disorder`, `chain_ptm.<chain>`, `chain_pair_iptm.<pair key>` (NaN becomes None, no arrays); `id` is `<model>:<name>:s<seed_index>:<sample>` unless `given_id` is set. See [`docs/poses.md`](docs/poses.md).
- `binding_metrics.poses.reference`: `Reference`, the structure that poses are placed on and measured against: a path, an `AtomArray` or a pose, the receptor chain, an optional binder chain, an optional `residue_map`, named residue sets in the reference numbering, and named partners (`Partner(structure, chains=None)`) already in the reference frame. A residue is a `ResidueKey(chain, number, icode)`. Frozen, with `validate()`, `content_hash()`, `to_dict()`, `from_dict()` and `normalize_references`. `Reference`, `Partner`, `ResidueKey`, `FrameOptions`, `FrameResult` and `Transform` can be pickled and copied (#134).
- `binding_metrics.poses.frame`: `superpose_receptor(pose, reference, ...)` pairs receptor residues (`residue_map`, else same number and insertion code, else a global alignment with BLOSUM62 and gap penalties -10 and -1), fits a Kabsch rotation on the paired C-alpha atoms (options: backbone atoms, a named residue set or the binding site, interquartile outlier rejection) and returns a `FrameResult` (pairing method, paired counts and fraction, receptor RMSD, C-alpha RMSD of the receptor, the binding site and every named residue set, the transform); a pose that cannot be placed is a failed result with a reason. `place_in_reference_frame`, `renumber_to_reference`. `FrameOptions` defaults `min_frame_residues` 10, `min_frame_fraction` 0.5, `min_sequence_identity` 0.8, `min_pair_fraction` 0.9, `site_cutoff_angstrom` 4.5.
- `pair_binder_residues(pose, reference, *, binder_chain, options=None)` (`binding_metrics.poses.frame`) pairs the binder of a pose with the binder chain of a `Reference` and returns a `ResiduePairing`; it needs the same number of polymer residues and every residue paired, and `reason` says why a binder does not pair. The keyword `binder_pairing` of `renumber_to_reference` renumbers the binder with it (#187).
- Pose agreement, in `binding_metrics.poses.agreement` and `binding_metrics.poses.symmetry`. `pairwise_peptide_rmsd(poses, binder_chain, *, kind="ca", symmetry="standard", residue_pairing="auto", cyclic_shift="off", refit=False, exclude_closure_mismatch=False, ...)` returns the symmetric `n x n` binder RMSD matrix (alpha carbons, backbone N, CA, C, O, or every heavy atom) of poses already in one frame (`refit=True` gives the shape RMSD); a pair that shares fewer than `min_shared_atom_fraction` (0.8) of the atoms has no value and a reason. `symmetry="standard"` matches interchangeable side-chain atoms (Asp, Glu, Leu, Val, Arg, Phe and Tyr rings, phosphate oxygens of Sep, Tpo, Ptr) and O/OXT of a free C-terminus (#133); a residue without an entry (BMT, ABA, ...) is listed in `unknown_residues`. `cyclic_shift="auto"` leaves the origin of a head-to-tail ring free. Also `pair_statistics`; `complete_linkage_clusters` (cutoffs 1.0 and 2.0 angstrom, ties by pose id rank); `medoid` and `medoids` (smallest mean distance among poses whose row has no undefined distance, ties to the lowest id, #135); `jaccard_matrix`, `interface_jaccard`, `contact_map_jaccard`, `heavy_atom_contacts` (5.0 angstrom) and `interface_residues` with `key_factory`; `positional_spread`. A statistic that needs more poses than it has is None with a `reason`, never NaN. The heavy-atom RMSD with the symmetric-atom minimum does not obey the triangle inequality.
- `binding_metrics.poses.aggregate`: per-group `mean`, sample standard deviation `std`, `min`, `max`, `median` with `n_ok`, `n_total` and `complete`, so a failed pose is counted and never averaged; `min_n_ok`; `reason_policy="keep"` keeps the values of a metric that has a `reason` and lists the reasons under `caveats`; pluggable statistics. `select_representatives` names one representative pose per group and overall by medoid, by native score (another score needs `confidence_direction`) or by a key function (`rank_by`). **Predictions and pre-flight**

- `--predictor af2`, `boltz2` and `protenix` without `--prediction-dir` start the model (from `PATH`, or `--prediction-conda-env`); without `--prediction-mode` the mode is `predict` for `af2` and `protenix`, `score` for `boltz2`; `--prediction-mode predict` is refused for OpenFold3.
- `PredictionRecord` is renamed `PredictedPose` and inherits from `Pose`. The structure reader and `check_chain_map` live in `binding_metrics.poses.pose`; `binding_metrics.predictors.record` still exports `check_chain_map`.
- The static pose-set path imports no simulation package (#138): a `score_pose_set` call with the static metrics imports neither `openmm` nor `mdtraj` and does not look for `openmm`, `simtk`, `mdtraj` or `pdbfixer`. `provenance.openmm_version` is read from the distribution metadata (None when not installed). `binding_metrics.metrics.sasa` imports mdtraj inside `calculate_buried_sasa` and `calculate_interface_sasa`; its module-level name `md` is gone.
- `score_pose_set` gives the EvoBind adversarial check the reference as design and each pose as second structure, with the per-atom pLDDT of the pose (#145); a pose without it has `evobind_adversarial_score` None and a `reason`, and pre-flight refuses a set of such poses under `preflight="error"`. In the check, residues pair by number and insertion code when the pairs agree in name, else by position if both chains have the same number of Cα atoms (`receptor_pairing` `"position"`, `n_superposition_residues` 0), else a `ValueError` says why (#108). `mean_plddt_binder`, `afm_mean_plddt_binder` and the Cβ pick identify residues by number and insertion code (#92, #102, #103).
- The OpenFold3 pre-flight warning for a head-to-tail binder says that `cyclic: true` only wraps the relative positions of the chain (#77).
- A receptor chain that is also a binder chain is a violation of kind `input` (constraint `chain_roles`, found "chain 'B' is named as the binder and as the receptor"), refused under `--on-incompatible error` (#180).

**Metrics, preparation and relaxation**

- `detect_interface_chains` counts amino-acid atoms instead of matching 28 residue names (#29). `D_AA_MAP` maps `MED` to D-methionine, no longer `DME` (decamethonium) (#15). `CYM` is a standard residue (#34).
- Chain-ID arguments are read as author IDs first, then as IDs of the OpenMM topology: `peptide_chain_id` and `receptor_chain_id` of `RelaxationConfig` (`binding-metrics-relax --peptide-chain`, #64) and the chain arguments of `compute_interaction_energy` and `binding-metrics-energy` (#112); `binding-metrics-run` passes author IDs. `detect_cyclization`, `detect_nonstandard`, `patch_nonstandard` and the `chain_id` of `restore_nonstandard_names` take the author ID for a topology read by `load_structure`; `patch_cyclic_topology` keeps taking the topology ID (#64, #113). `peptide_chain_label` of `detect_chains_from_file` is the chain ID OpenMM gives the file (#41).
- Residue labels in `peptide_cyclic_bonds`, `find_chain_breaks` (`residue_before`, `residue_after`), the heterogen removal log, the energy-step messages, `detect_cyclization` and the structural QC append the insertion code (#128). `compute_saltbridges` keys a residue by chain, number, insertion code and name; `detect_chains_from_file`, `detect_interface_chains` and the receptor detection of `compute_receptor_quality` count (number, insertion code) pairs (#120); the clashscore takes neighbours from that sequence (#121). `compute_structure_rmsd` reads the first model of a multi-model file and matches atoms by (chain, residue number, atom name, insertion code) (#116, #118).
- `save_cif(topology, positions, path, source_cif_path=...)`: a source residue is a run of rows with one (number, insertion code), the code goes to `pdbx_PDB_ins_code` (#122); one counter per author chain continues when the chain returns (#131); residues that share a number get `.` as `label_seq_id`, and `_struct_conn` partners are named by `ptnr*_auth_asym_id`, `ptnr*_auth_comp_id`, `ptnr*_auth_seq_id` and `pdbx_ptnr*_PDB_ins_code`, which `load_structure` reads (#132); hydrogens are told by `_atom_site.type_symbol` (H or D) when it exists (#142); residues of an author chain are paired with the source by name (#143). The restored residue number goes to `label_seq_id` and the `_struct_conn` rows (#40). Only the first model of a source is read.
- `compute_ramachandran`, `compute_omega_planarity` and the Ramachandran term of `compute_receptor_quality` pair the rows of biotite's `dihedral_backbone` with the residues (#48); a residue next to a cap still has no φ (or ψ, ω), as at a chain end.
- GAFF2 route: bond orders from the wwPDB Chemical Component Dictionary in biotite (#38); a bond that the topology lists twice is capped once. `sqm` runs with its own diagonaliser on one thread and the starting conformer is seeded (`random_seed`, `--random-seed`), so prep, relaxation and the energy step build byte-identical templates; `small_molecules` given as a list get the same seeded charges; stereocentres and E/Z bonds are read from the geometry; a residue that holds exactly the hydrogens of its template keeps them. Amide backbone charges (#61): a residue with an N-CA-C=O backbone is capped with ACE on N and NME on C where the external bond is a peptide bond, the caps are dropped from the template and their charge spread evenly over the kept atoms; a side-chain link or a residue without N, CA, C and O (the glutathione of 3P8F) keeps a methyl cap.
- Chain breaks (#60): `core.system.create_system_respecting_chain_breaks` builds the system from a copy of the topology without the C-N bond across each break of `find_chain_breaks` (C-N more than 2.0 A) and matches residues to templates with `ignoreExternalBonds=True`; used by `ImplicitRelaxation`, `compute_interaction_energy`, the receptor energy of `compute_receptor_quality` and `MDSimulation.setup`. An input without a break goes to `createSystem` unchanged.
- Relaxation and energy keep the peptide-receptor pair only; every other protein chain is removed after `strip_heterogens` with a warning (#42). `ImplicitRelaxation` ranks its chains with `io.structures.detect_chains` (#56); `prep_structure` and `strip_heterogens` take an amino acid by the definition of `detect_chains` and `drop_other_protein_chains`, Chemical Component Dictionary residues such as CYM, GLH, LYN, ABA, SAR, ORN included with biotite installed (#158, #159).
- Structural QC `bond_lengths` (#44): bonds from the topology, measured in the relaxed structure only; a bond over 2.5 A in the input is named in `detail`. `patch_cyclic_topology` rebuilds the bonds of a residue loaded without any, and the peptide bonds beside it (#43). `find_open_c_termini` and `require_closed_c_termini` (`core.system`) refuse a chain that ends in a standard residue without OXT, cap or closure bond (#114).
- `core.phosaa.hydrogen_definitions()` loads the hydrogen definitions of the phospho residues for the duration of an `addHydrogens` call (prep, relaxation, energy step) and restores the earlier state (#163); D residues of a linear peptide are renamed to their L templates for the hydrogen addition (#164).
- Receptor energy (#165, #166): `receptor_quality._receptor_energy` returns NaN with a `reason` and `error` when a modified residue that PDBFixer does not replace is removed from inside a chain; without PDBFixer `core.system.add_terminal_oxygens` adds the OXT, and a chain that still lacks atoms returns NaN with the hint `pip install binding-metrics[structure]` in `error`.
- `compute_receptor_quality` (#177): the energy dict of a failed term has `reason` (the text of `error`) on every failure path. The result has the top-level key `error_message` (`energy of model 1: <error>`, `energy of models 1, 2: <error>`) when the energy term failed on any model; the key is absent when every energy was computed.
- The interaction-energy section of the Markdown and HTML summary prints `A mode failed: <error_message>` under the table when `success` is true and `error_message` is set; the HTML escapes the text (#179).
- `ChainNotFoundError` is defined in `binding_metrics.metrics._common` and re-exported by `binding_metrics.cli.run`; both import paths give one class (#172).
- Trajectory SASA functions return nm^2; `PeptideBindingProtocol.analyze` reports A^2 (`sasa_buried`, `sasa_buried_mean`, `sasa_buried_std`, the "Buried SASA" line of `summary()`, `to_dict()`) (#58); `on_empty="warn"` is keyword-only after `probe_radius` (#157). `solvate` and `prepare_system` use seed 1 (`random_seed=None` restores fresh randomness) (#23).
- Console streams (#22): library warnings that reached stderr through the logging last-resort handler appear on stdout (for example `binding-metrics-relax` and `-report`), as do the `core.gaff_ncaa` messages in relax; `binding-metrics-prep` and `-solvate` keep warnings on stderr. `import binding_metrics` no longer imports OpenMM; names load on first access and a name whose optional dependency is missing raises an error that names the extra (#21). The tools call `configure_logging`, which sends records up to WARNING to stdout and ERROR and above to stderr (#22). `__version__` is read from the package metadata and is `0.0.0+unknown` in a tree that is not installed (#24).
- `METRICS.md` and `docs/metrics.md` are one document, `docs/metrics.md` (#36). `openfold.py` is split into `_openfold_run.py` and `_openfold_cli.py`, and the residue and water name sets live in `core/residues.py`; public names and import paths are unchanged (#34). The Coulomb constant, `DEFAULT_PH` and `DEFAULT_DEVICE` come from `binding_metrics._constants`; the metric modules call `import_biotite` of `metrics/_common.py` (#34). The `report` and `all` extras no longer list matplotlib; the `openfold` extra installs `openfold3` and `openfold3` is an alias (#36). Broad `except Exception` blocks catch the errors they expect or say why they stay broad (#25).
