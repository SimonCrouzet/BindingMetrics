# Changelog

All notable changes to BindingMetrics are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Issue numbers refer to the GitHub issue
tracker of the project. Example values come from the structures in `data/`: 1YCR (p53 peptide with
MDM2), 3P8F (SFTI-1 with matriptase), 1CWA (cyclosporin A with cyclophilin A), 1XY4 (somatostatin
analogue) and 3V3B (stapled peptide).

## [Unreleased]

### Results that change

Values from earlier versions differ in the cases below. A change reads "before -> after".

- **Inputs that a step could not take are refused before it runs (#75, #77, #90).** With the default `--on-incompatible error`, `binding-metrics-run` and `-batch` refuse an input that a requested step or model cannot take, where the run used to go on. An input that used to run and now stops, with the reason in the message:
  - a binder with a disulfide, lactam, staple or other cross-link sent to OpenFold3 (the `openfold` step, or `--predictor of3` run from here): 3P8F chain I (head-to-tail and disulfide) is refused; OpenFold3 0.5.0 reads only a head-to-tail closure and dropped the other link;
  - a binder residue that the OpenFold3 query builder cannot express (a residue with a backbone that is not a standard, X or peptide-linking CCD code) is refused before the model starts, as the query builder would have refused it; `--on-unmappable-residue x` still sends an `X` in its place;
  - `interface`, `geometry` (shape complementarity), `electrostatics` and `energy` on a structure with no receptor chain: 1XY4 (one chain) was `interface` error, `electrostatics` 0.0 kJ/mol and `shape_complementarity` NaN; it is refused;
  - the relaxation and the energy step on a binder with a cross-link that `core.cyclic` cannot patch (a thioether, a macrolactone), which raised `CyclizationError` after the preparation.
  `--on-incompatible skip` runs the steps that apply, `warn` runs everything, and `--prediction-dir` inputs only warn.
- **OpenFold3 seeds are honoured (#67).** OpenFold3 0.5.0 does not read a `seeds` field of the query JSON, and the toolkit always passed `--num_model_seeds=1`, which replaces the seeds of the runner YAML, so every run sampled with the seed that OpenFold3 generates from 42, 2746317213, whatever `seeds` the caller gave. The seeds now go to `experiment_settings.seeds` of the runner YAML and `--num_model_seeds` is passed only when asked for. Read from the OpenFold3 source (`validator.py`, `experiment_runner.py`) and confirmed in real runs of 0.5.0 (the directories `seed_42`, `seed_7`, `seed_11` and `seed_2746317213`).
  - Default run: seed 2746317213 -> 42 (`seed_2746317213/` -> `seed_42/`), so structures and confidence values of a default run change.
  - `--openfold-seeds 1 2 3` (or `seeds=(1, 2, 3)`): one seed, 2746317213 -> three seeds, in `seed_1/`, `seed_2/` and `seed_3/`. The pipeline scores the first sample of the first seed given: `--openfold-seeds 9 3` scores seed 9, the second directory, because the adapters count the seed directories in numeric order.
  - A `runner_yaml` keeps its own `seeds` unless `seeds` is given, which replaces them in the copy handed to OpenFold3. `num_model_seeds` defaults to None instead of 1; a number is still passed as `--num_model_seeds` and now cannot be combined with `seeds` (`ValueError`).
- **`binder_ca_rmsd` in OpenFold3 score mode.** `binding-metrics-run` and `-batch` measured the binder Cα RMSD against the input in `refold` mode only, on the premise that a scored prediction is templated on the input pose. Templates are per chain and carry no cross-chain geometry, so OpenFold3 places the binder itself in score mode too, and the RMSD in the receptor frame says how far its pose is from the input pose. In score mode, `binder_ca_rmsd` of `results["openfold"]` and `results["prediction"]` (columns `openfold_binder_ca_rmsd` and `prediction_binder_ca_rmsd`) goes from NaN to a number, also for an OpenFold3 output read with `--prediction-dir`. Example, from a stubbed OpenFold3 that returns 1YCR with the binder moved 2.0 A along z (synthetic output, no real run): NaN -> 2.00 A. The summary row is labelled "Refolding RMSD" in both modes.
- **`compute_interface_pae` of OpenFold3 output with a modified residue.** The function (and the registered metric `interface_pae`) sliced the PAE matrix by residue count and raised `ValueError: PAE matrix has 240 tokens but the structure has 176 residues` for any binder with modified residues, although `compute_openfold_metrics`, `compute_prediction_metrics` and `--predictor of3` had the token layout. It now builds the layout from the structure as `OpenFold3Parser.complete` does and cuts the blocks with it; a matrix that fits neither the layout nor the residue count still raises. 1CWA (real output of a `refold` run, seed 42, OpenFold3 0.5.0): `ValueError` -> `mean_interface_pae` 8.76 A (`max_interface_pae` 28.85 A, 75 binder tokens by 165 receptor tokens), the value of the other entry points.
- **Interface PAE and PDE of an OpenFold3 prediction with modified residues.** They were NaN with a `reason` for a binder with modified residues. OpenFold3 tokenises a residue of the standard set as one token and every other residue (a modified residue, a ligand) as one token per heavy atom, so the matrices of 1CWA are 240 x 240 for 176 residues. `OpenFold3Parser.complete(record)` now builds `record.tokens` from the predicted structure with the rule of the tokenizer (`tokenize_atom_array` in `openfold3/core/data/primitives/structure/tokenization.py`), so `compute_prediction_metrics`, `compute_openfold_metrics`, `PredictionSession.record` and `--predictor of3` cut the blocks at the chain boundaries. When the token count differs from the matrix size, the chains of the structure differ from those `chain_ptm` and `chain_pair_iptm` name, or the tokens of a chain are not one run, `record.tokens` stays None and `reason` says why. 1CWA (real output of a `refold` run, no MSA, seed 42): `mean_interface_pae` NaN -> 8.76 A, `max_interface_pae` 28.85 A, `mean_interface_pde` 0.68 A (seeds 7 and 11: 8.69 and 8.99 A); with the cyclic flag the same complex gave 10.9 to 11.4 A. The interface values of the standard-residue real outputs are unchanged: 44 sample files of 1YCR and 3P8F gave the same values and `reason` with and without the layout, and the rule gave the size of `pae` and `pde` in all 58 real sample files that were checked. New: `binding_metrics.predictors.of3.token_layout(record)` and `STANDARD_RESIDUE_NAMES`.
- **The template of an OpenFold3 `score` or `refold` run is given as a structure by default (#68).** `template_mode` is `"structure"` (`--openfold-templates structure`) where it was `"alignment"`: the query carries the template CIF itself (`template_cif_paths`, OpenFold3's CIF Direct Template Mode, OpenFold3 0.4.2 or later) and no A3M alignment. The ColabFold MSA server, which the runs use by default, overwrites an alignment path and leaves CIF paths alone, so a default run with the server on had no template at all (it was a template-free prediction with the keys of a scored one) and now has both:
  - 1YCR, `score`, one seed, server on: binder Cα RMSD to the crystal pose 1.62 -> 1.57 A, ipTM 0.847 -> 0.865; `results["prediction"]["templates"]` says `used` for both chains (the default `binding-metrics-run --predictor of3` run: 1.577 A, ipTM 0.865). With `--openfold-templates alignment` the run is the earlier one: no template, `replaced_by_msa_server`, a warning, a `Templates` row in the report.
  - With the server off the two routes gave the same prediction: 1YCR 1.12 A both; 1CWA, `score`, ipTM 0.9700 / 0.9701 and binder 0.402 / 0.403 A (`structure` / `alignment`), and in `refold` ipTM 0.9215 / 0.9214 and binder 0.702 / 0.704 A. One complex per case, one seed; none is a held-out complex.
  - The request key of every default `score` and `refold` request of OpenFold3 changes once (`options["template_mode"]` is `"structure"` instead of `"alignment"`): the prediction store does not reuse the entries made with the earlier default and runs the model again; they stay on disk and are used again by a request that asks for `alignment`. `alignment` stays fully available, also without the MSA server (the template is then read), with its A3M marker (`query-b<V>`) and the template accounting.
  - An OpenFold3 older than 0.4.2 is refused for `structure` before anything is written (`ValueError`, naming `--openfold-templates alignment`); `alignment` has no such need. `--openfold-templates alignment` with another `--predictor` is a usage error, as `structure` was; `structure` is accepted there because it is the default.
- **Head-to-tail binders of standard residues are sent to OpenFold3 as cyclic (#77).** The query of a binder with a head-to-tail bond and standard residues only carries `"cyclic": true` on the binder chain when the installed OpenFold3 is 0.4.5 or later (`binder_cyclic="auto"`, `--openfold-cyclic auto`, the default). OpenFold3 uses the field only to wrap the relative positions of the chain, from the token count of the chain, so for a binder with modified residues (D-amino acids, N-methylated residues, any residue sent through `non_canonical_residues`, selenocysteine), which OpenFold3 tokenises per atom, `auto` writes no flag, logs a warning and gives the reason in the result block; `--openfold-cyclic on` still forces it (with a warning for such a binder) and `off` never writes it. Measured, one complex per case (OpenFold3 0.5.0, no MSA, one sample per seed, the weights have very probably seen both entries): 1CWA chain C (D-Ala, N-methylated residues; `refold`, receptor template read), seeds 42 / 7 / 11, with the flag against without: ipTM 0.784 / 0.776 / 0.809 against 0.921 / 0.922 / 0.912, binder Cα RMSD against the input 3.01 / 4.66 / 4.75 A against 0.70 / 0.47 / 0.51 A. 3P8F chain I (SFTI-1, standard residues; one seed): C-N distance of the ring 1.38 A with the flag, 7.40 A without (1.44 A in the input), binder Cα RMSD 0.38 against 0.65 A. Before -> after: the default query of 1CWA chain C no longer carries `cyclic: true` (it did, from the commit that added the field, for any head-to-tail binder); 3P8F chain I and other SFTI-1-like peptides keep it, and 1YCR chain B and the receptor chains are unchanged. A head-to-tail binder with an older or unreadable OpenFold3 is left linear and logged as a warning, and the result block says why. The mechanism (`cyclic_offset` in `relpos.py`) is read from the source and run on OpenFold3's function on CPU; no ablation of the model was made.
- **`binder_ca_rmsd` for outputs of ColabFold, Boltz-2 and Protenix.** `--predictor af2|boltz2|protenix --prediction-dir DIR` (and `prediction_dir` of `run_pipeline` and `run_batch`) took no reference structure for these models, so `binder_ca_rmsd` of `results["prediction"]` was NaN with no reason. It is now measured against the input pose in the receptor frame, as for OpenFold3 (the binder is placed by the model in every mode): NaN -> the RMSD in angstrom, or NaN with a `reason` when a chain of the input is not in the prediction under the same ID (give `--prediction-binder-chain` and `--prediction-target-chain`) or the receptor has another number of C-alpha atoms. `delta_com_angstrom` was already measured.
- **Binder RMSD against a reference (#93).** `binder_ca_rmsd` of `compute_openfold_metrics` superposes on the binder Cα when no `receptor_chain` is given, as documented, and is NaN with a `reason` when the receptor Cα counts of the prediction and the reference differ or are fewer than 3. It used to measure the raw distance between two frames in both cases. `binding-metrics-run` always passes the receptor chain, so its value changes only for a receptor of different length.
  - An identical structure rotated by 40 degrees and translated: without a receptor chain 7.20 -> 0.00 A; with a receptor of another length 7.20 -> NaN.
- **RMSD superposition (#13).** The Kabsch rotation was applied in the wrong direction, so any pair
  that was not already superposed came out too high.
  - `compute_structure_rmsd`: 1YCR rotated by 30 degrees and translated, `rmsd` 11.23 -> 0.00 A and
    `rmsd_design` 6.80 -> 0.00 A. It also reads only the first model of a multi-model file.
  - Relaxation: `rmsd_md_final`, `receptor_rmsd_md_final` and `receptor_drift_mean` use the same routine.
- **Waters, ions and ligands are dropped by default (#14).** `hetero="ignore"` keeps amino-acid atoms,
  AMBER protonation variants and ACE/NME/NH2 caps. `hetero="keep"` selects every atom of the chain as before;
  water and ion atoms have no SASA and count as zero area, where they used to make the sum NaN.
  - ΔSASA: 1CWA `delta_sasa` NaN -> 985.4 A^2, 3P8F NaN -> 1508.3 A^2. 1YCR has no waters and is unchanged.
  - H-bonds: 1CWA 6 -> 5 (`hbond_energy` -10.56 -> -8.22 kcal/mol), 3P8F 11 -> 9 (-20.42 -> -16.67).
  - Shape complementarity: `sc` 1CWA 0.722 -> 0.750, 3P8F 0.732 -> 0.738.
  - Void volume: interface atoms 1CWA 153 -> 123, 3P8F 227 -> 207.
- **Solvation parameters of `delta_g_int` (#18).** The old table gave every N +0.063 and every O
  +0.024 kcal/mol/A^2. Five atom types after Eisenberg and McLachlan (1986) replace it: C -0.016,
  S -0.021, neutral N/O +0.006, O(-) +0.024, N(+) +0.050 (values as tabulated by Krissinel and Henrick, 2007).
  - `delta_g_int`: 1YCR -0.77 -> -11.05 kcal/mol, 1CWA +1.26 -> -6.11 (water-free input), 3P8F NaN -> -4.97.
- **Buried area and `delta_g_int` on heavy atoms (#39).** With explicit hydrogens the surface of a heavy atom
  was partly taken by its hydrogens, which carry no solvation parameter, and polar + apolar did not add up to
  `delta_sasa`. Hydrogens are dropped before the areas (`hydrogens="keep"` restores the old atom set).
  - 1YCR relaxed by `binding-metrics-run` (851 H of 1670 atoms): `delta_sasa` 1552.4 -> 1488.4 A^2, polar + apolar
    651.4 -> 1488.4 A^2, `delta_g_int` -0.95 -> -10.50 kcal/mol. The bundled files without hydrogens are unchanged.
- **Void volume honours `probe_radius` (#17).** A void must be closed to the probe in the complex and
  open for each chain alone; before, the probe was ignored and a cavity walled by one chain counted.
  - `void_volume_A3` at the default probe: 1YCR 0.25 -> 55.875, 3P8F 0.38 -> 31.875, 1CWA 0.50 -> 16.25 A^3.
- **Clashscore of `compute_receptor_quality` (#16).** Covalent links (disulfides, ring closures, lactams,
  staples) and N...O hydrogen-bond pairs are no longer counted; `exclude_bonded=False` restores the count.
  - Clashscore: 3P8F chain I 66.67 -> 0.00 (`molprobity_score` 3.863 -> 2.068), 3P8F chain A 18.24 -> 0.54.
  - Clashscore: 1XY4 52.17 -> 0.00, 1YCR chain A 11.35 -> 7.09, 1CWA chain A 2.37 -> 0.00, 3V3B chain C 31.25 -> 0.00.
- **GAFF bond orders of non-canonical residues (#38).** Bond orders were perceived on a graph without
  hydrogens and came out single. They now come from the wwPDB Chemical Component Dictionary in biotite.
  - 1CWA: MeBmt has 17 hydrogens, not 19, and its CE=CZ bond relaxes to 1.340 A, not 1.544 A (crystal 1.336 A).
  - 1CWA `raw_interaction_energy` -268.4 -> -299.7 kJ/mol, `relaxed_interaction_energy` -280.9 -> -299.7
    kJ/mol (`--md-duration-ps 0`, seed 1, CUDA; the values after the GAFF2 entries below).
  - The backbone C=O of 0EH and MK8 (3V3B) was read as C-OH.
  - IAM (1XY4): PDBFixer lists the IAM-THR peptide bond twice, so the capped molecule got two caps on the backbone C
    and IAM fell back to single bonds. A bond that the topology lists twice is capped once, and IAM takes the
    dictionary bond orders: `ncaa_bond_order_source` `single_bonds` -> `ccd`, hydrogens 24 -> 18, an aromatic ring
    instead of cyclohexane.
- **GAFF2 charges repeat from run to run.** `sqm` picked its diagonalisation routine by timing seven of
  them at start-up, and one of them ended the AM1 minimisation of MeBmt in another geometry. The BMT template
  charges changed by up to 9e-4 e between builds (0.013 e in the AM1-BCC output), prep, relaxation and the
  energy step each built their own template, and the relaxed 1CWA complex changed between runs. `sqm` now runs
  with its own diagonaliser on one thread, and the conformer that the charges start from is seeded
  (`random_seed` of `parameterize_ncaa_residues`, default 1, set by `--random-seed`). The three steps build
  byte-identical templates.
  - 1CWA, four runs of one command (`--md-duration-ps 0`, seed 1, CUDA) gave three results: minimised complex
    energy -21555.1, -21562.7 or -21563.2 kJ/mol; `relaxed_interaction_energy` -297.1, -298.6 or -298.9 kJ/mol;
    buried area 1006.4, 1010.3 or 1007.9 A^2. After the change every run gives the same files.
- **AM1-BCC charges of GAFF2 residues use the stereochemistry of the structure.** The residue graph had none,
  so the conformer that `sqm` minimises was a random stereoisomer: MeBmt (BMT, 1CWA) was embedded with CA R,
  CB S, CG2 R and a Z double bond, against S, R, R and E in the structure. Stereocentres and E/Z bonds are read
  from the geometry now. AM1-BCC charges depend on the conformer, so a residue's charges also change with
  `random_seed`: MeBmt differs by up to 0.065 e between seeds 1 and 2.
  - 1CWA: BMT template charges change by up to 0.047 e and ABA by up to 0.017 e. Minimised complex energy
    -21562.7 -> -21553.4 kJ/mol, `raw_interaction_energy` -280.2 -> -280.4, `relaxed_interaction_energy`
    -298.6 -> -298.5, buried area 1010.3 -> 996.8 A^2, void volume 9.9 -> 4.9 A^3, `sc` 0.685 -> 0.684.
- **GAFF2 residues keep their relaxed hydrogens.** `parameterize_ncaa_residues` dropped the hydrogens of every
  GAFF2 residue and injected the ones RDKit places for the heavy atoms, in prep, relaxation and the energy step.
  The energy step therefore evaluated a relaxed structure with unrelaxed hydrogens on such a residue: the complex
  energy of 1CWA was 124 kJ/mol above the relaxation minimum, against 0.02 kJ/mol for complexes without a GAFF2
  residue. A residue that holds exactly its template's hydrogens (same names on the same parent atoms) now keeps
  them and their positions; a residue without hydrogens, or with others, is built as before.
  - 1CWA (`--md-duration-ps 0`, seed 1, CUDA), before -> after: minimised complex energy -21553.4 -> -21552.6
    kJ/mol, energy-step `raw_e_complex` -21429.4 -> -21552.6 (gap to the minimum 124.0 -> 0.02),
    `raw_interaction_energy` -280.4 -> -299.7, `relaxed_interaction_energy` -298.5 -> -299.7, buried area
    996.8 -> 996.3 A^2, void volume 4.9 -> 5.6 A^3, `sc` 0.684 -> 0.685. Prep is unchanged.
- **Charges of `small_molecules` given as a list repeat from run to run.** The listed molecules went to
  `GAFFTemplateGenerator`, whose own AM1-BCC call had the `sqm` timing problem above. They now get the same
  seeded, single-diagonaliser charges before the generator is built; charges set on a molecule are kept.
- **D-amino-acid and N-methyl names survive prep and relax (#15).** The relaxed CIF of 1CWA had
  `ALA ... NMG` where the input has `DAL ... SAR`; it now keeps the input names.
- **Ligand RMSD (#37).** `calculate_ligand_rmsd` fitted the ligand a second time and returned 0 for a
  rigid-body shift. 1YCR chain B moved 5 A against chain A: `ligand_rmsd` [0, 0] -> [0, 0.5] nm.
- **Ring-closing phi, psi and omega (#15).** For a head-to-tail peptide, `compute_ramachandran` and
  `compute_omega_planarity` score the closing amide bond (C(last) to N(first) within 2 A).
  - 1CWA chain C: residues 9 -> 11, `n_d_residues` 0 -> 1, favoured/allowed/outlier 66.7/22.2/11.1 ->
    72.7/18.2/9.1 %, omega bonds 10 -> 11.
  - 3P8F chain I: residues 12 -> 14, 91.7/0.0/8.3 -> 85.7/7.1/7.1 %, omega outliers 1 -> 2.
- **Coulomb energy and salt bridges for D, HIP and phospho residues (#29).** The charge tables knew only
  L-residue names. D codes now map to their L counterpart, HIP carries +1 and SEP/TPO/PTR carry -2.
  - An all-D peptide (DLY) against ASP at 4 A: `coulomb_energy_kJ` 0.0 -> -101.3, equal to its L twin.
  - 1YCR (-91.59 kJ/mol) and 3P8F (-299.59 kJ/mol) do not change.
- **Chain detection (#29).** `detect_interface_chains` counts amino-acid atoms instead of matching 28
  residue names. A 20-residue ALA receptor with a 5-residue DAL peptide: `('A', None)` -> `('B', 'A')`.
- **Seeding (#23).** `solvate` and `prepare_system` used unseeded randomness for ions and hydrogens and
  now use seed 1 (`random_seed=None` restores fresh randomness).
  - `compute_receptor_quality`, 1YCR chain A energy: 4828.7, 4834.2 and 2337.5 kJ/mol in three runs
    -> 4371.8 kJ/mol every time.
- **`MED` for D-methionine (#15).** `D_AA_MAP` mapped `DME` to MET, but `DME` is decamethonium in the
  Chemical Component Dictionary. `MED` is now the D-methionine code and `DME` is no longer a D residue.
- **`HIN` in EvoBind residue matching.** `HIN` pairs with `HIS` as a histidine variant, so
  `*_resname_mismatch_fraction` does not count it as a mismatch.
- **Binder pLDDT of the EvoBind scores with insertion codes (#92).** `mean_plddt_binder` and
  `afm_mean_plddt_binder` tell residues apart by residue number and insertion code, as the OpenFold3 metrics
  do, so residues 1 and 1A are two residues. Structures without insertion codes are unchanged.
  - A binder with residues 1, 1A and 2 and pLDDT 10, 30 and 50: `mean_plddt_binder` 35.0 -> 30.0, and
    `evobind_score`, which divides by it, moves with it.
- **EvoBind Cβ pick and residue pairing with insertion codes (#102, #103).** A residue is identified by residue
  number and insertion code, so residues 52 and 52A are two. The Cβ pick had dropped the second one, and the
  adversarial check paired residues by number alone. Structures without insertion codes are unchanged.
  - A binder with residues 1, 1A and 2 whose Cβ lie 6.0, 12.0 and 7.10 A from the nearest receptor Cβ:
    `if_dist_pep_to_rec` 6.55 -> 8.37 A.
  - Two receptors that differ by one residue called 4A in the second one: `compute_evobind_adversarial_check`
    raised a shape error from `superimpose`; it now pairs the 11 shared residues (`n_superposition_residues` 11).
- **EvoBind adversarial check against a second model that numbers every chain from 1 (#108).** The receptor of
  1YCR is numbered 25-109 and the same chain in the second model 1-85. The numbers overlap but name other
  residues (93% of the pairs had different names), so the pairing by residue number was wrong and the call
  raised. Residues are now paired by number and insertion code only when the pairs agree in name. Otherwise, or
  when a number and code repeats in a chain, they are paired by position if both chains have the same number of
  Cα atoms; the receptor interface is then mapped by position too and `n_superposition_residues` is 0. If
  neither pairing agrees in residue names, or the chains differ in length, a `ValueError` says why. Structures
  that pair consistently by number give the same values.
  - 1YCR against a copy of itself renumbered from 1: `ValueError` -> `delta_com_angstrom` 0.00 A,
    `receptor_pairing` `"position"`, `n_superposition_atoms` 85.
  - 1YCR against a copy whose receptor repeats one residue number (same number of residues): `ValueError` ->
    paired by position (`receptor_pairing` `"position"`, `n_superposition_atoms` 85).
- **OpenFold3 query sequences (#75, #76).** D-amino acids and modified residues became lower-case letters
  in the query sequence (`DAL` -> `a`, `SEP` -> `s`), which OpenFold3 turns into unknown residues, and
  CYX, HID, HIE, HIP and names gemmi does not know were dropped from it, so the chain came out shorter
  without a message. D-amino acids, N-methylated and other modified residues now keep their parent
  letter in upper case and go to `non_canonical_residues` with their CCD code (the toolkit's NMG and NMA
  as SAR and MAA); protonation variants take the parent letter.
  - 1CWA chain C: `allvtaglVlA` -> `ALLVTAGLVLA`, with nine residues (`DAL`, `MLE`, `MVA`, `BMT`, `ABA`,
    `SAR`) in `non_canonical_residues`. 1QJB chain Q: `ARSHsYPA` -> `ARSHSYPA` with `{5: SEP}`. 3V3B chain C:
    `TFNLWRLLl` (nine letters, `0EH` left out) -> `TFXNLWRLLL` with `{3: 0EH, 10: MK8}`.
  - **Deliberate behaviour change:** a residue with a backbone that OpenFold3 cannot take (not a standard,
    variant, D- or peptide-linking CCD residue) raises `UnmappableResidueError` before any file is
    written or process started, where it was left out or turned into a wrong letter. The message names
    the chain and the residues. `on_unmappable_residue="x"` (`--on-unmappable-residue x`) restores a
    query with `X` at their positions and a logged warning.
- **Interface PDE and PAE of OpenFold3 output (#33).** A ligand or modified residue tokenised per atom
  shifted the residue-based slice onto the wrong block. The values are NaN with a `reason` now.
- **Batch status and order (#19, #32).** A sample whose steps failed had `batch_status` `ok`; it is
  `partial` now, with `batch_failed_steps` and `batch_failed_reasons`.
  - The exit code is non-zero when no sample is `ok`. With `--workers > 1` the CSV rows follow the input order.
- **`--md-duration-ps` from 1 to 9 (#27).** A duration below the 10 ps save interval failed with an
  IndexError after the MD had run. The run saves one frame at the end and completes.
- **Console streams (#22).** Library warnings that reached stderr through the logging last-resort handler
  appear on stdout, for example in `binding-metrics-relax` and `-report`; the `core.gaff_ncaa` messages
  appear in relax. `binding-metrics-prep` and `-solvate` keep warnings on stderr.
- **Warnings of `compute_openfold_metrics`** name the line that called it.
- **Structural QC bond lengths (#44).** The `bond_lengths` check took its bond list from input distances, so
  atoms that PDBFixer had rebuilt inside a clash counted as bonds, and a relaxation that resolved the clash
  failed the check. Bonds now come from the topology and are measured in the relaxed structure only; the
  limits are unchanged, and a bond already over 2.5 A in the input is named in `detail`.

- `binding_metrics.predictors.store`, the run-once store of model predictions. `PredictionRequest` describes a prediction by everything that changes it (model and version, mode, seeds, samples, options, chain roles, and the content hash of the input file, never its path); `request.key()` is a SHA-256 of that description, the same on every machine. `PredictionStore(root)` keeps one directory per key (`request.json`, `STATUS.json`, `outputs/`), returns a finished run with `lookup` and `get_or_run`, registers outputs the user made with `adopt` (an adopted output belongs to the request name, so two samples with equal input files keep their own), and runs the missing requests of a list in one batched call with `run_missing`. A run is written to a temporary directory and renamed into place under an `fcntl` lock per key: a killed run never looks finished, and two processes asking for one request run the model once. A failed run is recorded with the exception text and is not retried unless `rerun=True`; a model that cannot start here raises `PredictionUnavailableError` and records nothing.
- `PredictionSession(store, runners, parsers)` (`binding_metrics.predictors.session`), the per-sample handle for metrics: `record(request)` runs the model on the first miss only and parses once, `prefetch(requests)` runs the missing ones in one batch, `adopt(request, directory)` registers a directory for parse-only use, and `stats()` counts requests, memo hits, store hits, adopted outputs, misses, runs, failures and parses, so "this model ran once" can be read from a result file.
- `PredictionRunner` (`binding_metrics.predictors.runners`), the base class of a model runner (`prepare`, `run`, optional `supports_batch` and `run_many`, `is_available`, `version`), and `OpenFold3Runner` (`binding_metrics.predictors.of3_runner`), which starts OpenFold3 through `run_openfold_scoring`, `run_openfold_refolding`, `run_openfold_batched` and `run_openfold`. `OpenFold3Runner.make_request` writes every setting that changes the output into the request, the user-default `runner.yml` of OpenFold3 included. Chain IDs are the user's IDs after each record's `chain_map`; `design` may also be a structure path. The result has the keys of `compute_evobind_adversarial_check` (the `afm_` keys describe the second prediction whatever model made it) plus `design_model` (None for a path) and `adversary_model`. The runners differ and the command line asks them. `PredictionRunner` has `supported_modes` (a frozenset, `{"predict"}` by default; a runner that names the modes it builds an input for `run_modes` is read through that name), `default_mode` (None: the default of the `mode` parameter of its `make_request`) and the optional `output_chain_map(request)` (`{chain ID in the prediction: chain ID in the input}`, None by default). `--prediction-mode` defaults to the mode of the runner (`--openfold-mode` for of3, `score` for boltz2, `predict` for af2 and protenix) and a mode the runner does not run (of3 `predict`, af2 and protenix `refold`, `score` and `score-lock`) is a usage error that names the modes it runs; `predict` is no longer refused for a run from here. The settings reach a runner only when its `make_request` has the keyword, and one it lacks is a `ValueError` that names the option and the model. `binding_metrics.predictors` exports the three runners.
- `--prediction-cyclic {auto,on,off}`, `--prediction-no-msa-server`, `--prediction-conda-env NAME` and `--prediction-lock-threshold ANGSTROM` for `binding-metrics-run` and `-batch` (keywords `prediction_cyclic`, `prediction_use_msa_server`, `prediction_conda_env` and `prediction_lock_threshold` of `run_pipeline` and `run_batch`): the settings of the `--predictor` route for every model. `--prediction-cyclic` is `cyclic: true` for OpenFold3 and Boltz-2 and `covalent_bonds` for Protenix and is refused for ColabFold; `--prediction-no-msa-server` is `single_sequence` for ColabFold, `msa: "empty"` for Boltz-2, `--use_msa false` for Protenix and the OpenFold3 setting for of3; the lock threshold is the threshold of the forced template of Boltz-2's `score-lock`, 2.0 angstrom by default, and is refused for another runner or mode. `--openfold-cyclic`, `--openfold-no-msa-server` and `--openfold-conda-env` stay the settings of the OpenFold3 step and of `--predictor of3`, where giving both spellings with different values is a usage error; for another model the `--openfold-*` option other than its default is a usage error that names the generic one, so the default environment `openfold3` is never handed to another model. The settings of a run are refused with `--prediction-dir`.
- The chain IDs of a prediction: the runner's `output_chain_map(request)` is passed to the reader as `chain_map` unless `--prediction-binder-chain` or `--prediction-target-chain` is given, so the metrics of a ColabFold prediction (receptor `A`, binder `B`) find the chains under the IDs of the input. A prediction that lacks a chain of the input gets a `reason` that names the model, the chains it has and the options that fix it. Failure warnings name the model.
- `ColabFoldRunner` (`binding_metrics.predictors.af2_runner`): the prediction store can start AlphaFold2 and AlphaFold-Multimer through `colabfold_batch`. One FASTA record per request, receptor then binder joined by `:`, so the prediction has chain A for the receptor and B for the binder; mode `predict` only (other modes raise and name `--prediction-dir`); `use_msa_server=False` writes `--msa-mode single_sequence`; the seeds are consecutive integers from 0 (`--random-seed` and `--num-seeds`) and `num_samples` is `--num-models`. It refuses before anything is written a chain with a residue AlphaFold2 cannot take (D-amino acid, N-methylated, phosphorylated or any other component with its own Chemical Component Dictionary code, selenocysteine), naming the chain and the residues. Its request holds the sequences and no input file, so two poses of one receptor and binder share one stored run. Custom parameters are `weights`, a `--data` directory identified by content; a directory without the marker file of the model type in `params/` is refused, because `colabfold_batch` would download the default parameters over it. A ColabFold job that exits with status 0 without writing its structures (a failed MSA request, GPU out of memory) is recorded as a failed run with the line ColabFold logged. Read in the source of ColabFold v1.6.3 and tested with a stand-in process; not run against ColabFold.
- `ProtenixRunner` (`binding_metrics.predictors.protenix_runner`): the prediction store can start Protenix through `protenix pred`. It writes the input JSON from the two chains of the input structure (the receptor is entity 1 and the binder entity 2, each with `id` set to its chain ID in the input, modified residues as `CCD_<code>` modifications), runs mode `predict` only (Protenix takes templates as alignment files, so `refold`, `score` and `score-lock` raise and name the `constraint` section as the documented way to steer a prediction), always asks for the per-atom confidence file (`--need_atom_confidence true`) and writes every setting that changes the output into the request: model name, dtype, seeds (`[101]` by default), samples, `use_msa_server`, `msa_server_mode`, `constraints`, `covalent_bonds`, the closure setting, `extra_args` and the size of the default weights file. A binder with a head-to-tail bond or a disulfide gets the matching `covalent_bonds` (`binder_cyclic="auto"`); a closure that cannot be placed raises instead of predicting a ring as a linear chain. A residue Protenix cannot take is refused before anything is written, naming the chain and the residues. Custom weights are a directory with `<model_name>.pt`, given through a temporary `PROTENIX_ROOT_DIR` because `protenix pred` has no option for it. A sample that failed (`ERR/<name>.txt`, `ERR/error.txt`), a seed or sample without its structure, summary or full-data file, and an MSA search that failed (after which Protenix continues with the sequence itself as the MSA) are recorded as failures with what Protenix recorded. Read in the source of Protenix 2.0.0 (commit 85767b8) and tested with a stand-in process; not run against Protenix.
- `Boltz2Runner` (`binding_metrics.predictors.boltz2_runner`) starts `boltz predict` for the prediction store, in the current environment or through `conda run -n ENV`. It builds the YAML from a complex structure, with one protein entity per chain under the chain IDs of the input, the sequence and the modified residues of the OpenFold3 chain reader (CCD codes in `modifications`), `cyclic: true` for a head-to-tail binder (`binder_cyclic="auto"`), and `msa: "empty"` without the MSA server. The modes: `predict` (sequences only), `refold` (the receptor templated from a CIF of the input), `score` (each chain templated from its own CIF) and `score-lock` (one CIF of both chains in the input frame, listed for both chains with `force: true` and a threshold). Boltz-2 documents no default for the threshold: `lock_threshold_angstrom` defaults to 2.0 A, this package's choice, and is part of the request key. A request takes one seed (default 42) and `num_samples` structures (default 5); custom weights go as `--checkpoint`. The template CIFs name every residue after its parent (`MLE` becomes `LEU`), because Boltz-2 reads a modified residue of a template as `X`. A failure of `boltz predict` keeps its reason: a non-zero exit raises `Boltz2RunError` (a `CalledProcessError` whose text has the key line of the output, advice for known failures and the command), and a run that exits with status 0 without output raises `RuntimeError` with Boltz-2's message. A residue that Boltz-2 cannot express raises `ValueError` naming the chain and the residues before any file is written. This runner has been run for real once, on Boltz-2 v2.2.1 in single-sequence mode with `--no_kernels`, through the store and the adapter: `predict`, `refold`, `score` and `score-lock` on 1YCR and `score-lock` on 1CWA, and the adapter read the outputs cleanly. The exit-0-without-output paths, `use_msa_server=True` and a conda environment were not exercised, and the pose-pinning effect of `score-lock` is not yet shown.
- `docs/metrics.md` records what the Boltz-2 modes did on one complex (1YCR with the binder moved rigidly by 3, 6 and 10 angstrom and by two rotations, Boltz-2 v2.2.1, single-sequence mode, three seeds of one diffusion sample): `score` returned the same structure for every pose, `score-lock` kept the prediction within about the threshold of the supplied pose and not on it, and its ipTM and interface PAE worsened with the displacement from 6 angstrom or 30 degrees on. The table and the limits of that measurement (one complex that the model very likely saw in training, three seeds) are under `Boltz2Runner`, "Observed behaviour (Boltz-2, one complex)". The pre-flight warning for Boltz-2 `score-lock` says that its effect was measured once, on one complex, where it said that the source was never run.
- `binding_metrics.poses`: a pose is one structure of a complex, classified by its origin. `Pose` is the abstract base class and has three kinds: `PredictedPose` (the output of a co-folding model, the former `PredictionRecord`), `DockedPose` (the output of a docking or design tool: its own `scores`, a `decoy` flag) and `ExperimentalPose` (a crystal, NMR or EM structure: `method`, `resolution_angstrom`, `pdb_id`, `quality`). Every pose has `kind`, `id`, `structure_path`, `atoms()` (chain IDs of `chain_map` applied, gzip read, cached), `chain_map`, `provenance` (JSON scalars), `content_hash()` (SHA-256 of the file bytes, or of a canonical serialisation of an in-memory `AtomArray` with coordinates rounded to 0.001 A) and `native_scores()`, what the tool that made the pose reported, flat and values only. A computed metric is never stored on a pose. `DockedPose` and `ExperimentalPose` are frozen dataclasses built with `from_file(path, *, ..., id=None, **provenance)` or `from_atoms`; a bare structure that is neither (a decoy displaced by hand, a fixture) is a `DockedPose` with `decoy=True` and no `program`. The names load on first access, and importing them imports numpy and the standard library only. [`docs/poses.md`](docs/poses.md) describes them.
- `PredictedPose.native_scores()` (`avg_plddt`, `ptm`, `iptm`, `gpde`, `ranking_score`, `has_clash`, `disorder`, then `chain_ptm.<chain>` and `chain_pair_iptm.<pair key>`; NaN becomes None; the arrays are not in it), `kind`, `id` (`<model>:<name>:s<seed_index>:<sample>` unless `given_id` is set), `content_hash()`, and the optional keyword fields `provenance` and `given_id`.
- `binding_metrics.poses.reference`: `Reference`, the structure that poses are placed on and measured against, an analysis role that any pose can play. It takes a path, an `AtomArray` or a pose (a bare path or array becomes an `ExperimentalPose`), the receptor chain, an optional binder chain, an optional `residue_map` from pose residues to reference residues, named residue sets in the numbering of the reference, and named partners (`Partner(structure, chains=None)`) already placed in the reference frame. A residue is a `ResidueKey(chain, number, icode)`, so 52 and 52A are two residues. Frozen, with `validate()` against the structure (every problem in one error), `content_hash()` through the pose machinery, `to_dict()` and `from_dict()` (a structure is recorded by path and hash and checked on reading), and `normalize_references` for one reference or a mapping of variants. `Reference`, `Partner`, `ResidueKey` and the frame classes of `binding_metrics.poses.frame` (`FrameOptions`, `FrameResult`, `Transform`) can be pickled and copied, so they can go to the worker processes of a pool (#134). Importing the module imports numpy and the standard library only.
- `binding_metrics.poses.frame`: places a pose in the frame of a reference receptor. `superpose_receptor(pose, reference, ...)` pairs the receptor residues (a `residue_map`, else the same number and insertion code, else a global sequence alignment with BLOSUM62 and gap penalties -10 and -1, so trimmed, renumbered and insertion-coded constructs pair), fits a Kabsch rotation on the paired C-alpha atoms (no outlier rejection by default; options: backbone atoms, a named residue set or the binding site, interquartile outlier rejection), and returns a `FrameResult` with the pairing method, the paired counts and fraction, the receptor RMSD, the C-alpha RMSD of the whole receptor, the binding site and every named residue set in the final frame, and the transform. A pose that cannot be placed (chain missing, too few or too small a fraction of paired residues, sequence identity below 0.8, collinear fit atoms) is a failed result with a reason. `place_in_reference_frame` returns a transformed copy of the atoms and `renumber_to_reference` gives the paired receptor residues the numbers of the reference. Every threshold is a field of `FrameOptions` with a documented default (`min_frame_residues` 10, `min_frame_fraction` 0.5, `min_sequence_identity` 0.8, `min_pair_fraction` 0.9, `site_cutoff_angstrom` 4.5).
- Pose agreement, in `binding_metrics.poses.agreement` and `binding_metrics.poses.symmetry` (import them from these modules). `pairwise_peptide_rmsd(poses, binder_chain, *, kind="ca", symmetry="standard", residue_pairing="auto", cyclic_shift="off", refit=False, ...)` returns the symmetric `n x n` matrix of binder RMSD between poses that are already in one frame (the peptide is not refitted; `refit=True` gives the shape RMSD) for the alpha carbons, the backbone (N, CA, C, O) or every heavy atom. Residues are paired by `ResidueKey` (chain, number, insertion code) or by position, residues and atoms missing in one pose are dropped and a pair that shares fewer than `min_shared_atom_fraction` (0.8) of the atoms has no value and a reason. With `symmetry="standard"` the interchangeable side-chain atoms (Asp OD1/OD2, Glu OE1/OE2, Leu CD1/CD2, Val CG1/CG2, Arg NH1/NH2, the Phe and Tyr ring flip, the phosphate oxygens of Sep, Tpo and Ptr) and O and OXT of the free C-terminal carboxylate of a linear binder, when both poses carry them (#133), are matched in the labelling with the smallest RMSD; D-residues, protonation variants and N-methylated residues use the entry of their L parent, and a residue without an entry (BMT, ABA, ...) is compared as named and listed in `unknown_residues`. A head-to-tail ring has no terminus and no chain break in this code; `cyclic_shift="auto"` leaves the ring origin free for rings that are closed head to tail. `pair_statistics` gives minimum, mean and maximum inside and between groups; `complete_linkage_clusters` clusters by complete linkage (own implementation, ties broken by pose id rank, cutoffs default to 1.0 and 2.0 angstrom); `medoid` and `medoids` pick the pose with the smallest mean distance to the others, among the poses whose row has no undefined distance, ties going to the lowest id (#135); `jaccard_matrix`, `interface_jaccard`, `contact_map_jaccard`, `heavy_atom_contacts` and `interface_residues` compare interfaces and contact maps (5.0 angstrom heavy-atom cutoff); `positional_spread` gives the per-position scatter of the alpha carbons. Residue sets (contacts, interface residues, the positions of the spread) hold `ResidueKey` objects; `key_factory` of `heavy_atom_contacts` and `interface_residues` overrides the key type. A statistic that needs more poses than it has is None with a `reason`, never NaN. The heavy-atom RMSD with the symmetric-atom minimum does not obey the triangle inequality.
- `binding_metrics.poses.aggregate`: per-group statistics over per-pose rows (`mean`, sample standard deviation `std`, `min`, `max`, `median`) with `n_ok`, `n_total` and `complete`, so a failed pose is counted and never averaged; `min_n_ok`; a dictionary-level `reason` excludes the values of that metric for that pose (`reason_policy="keep"` keeps them and lists the reasons under `caveats`); pluggable statistics. `select_representatives` names one representative pose per group and overall by medoid, by native score (the direction of each score is documented, and another score needs `confidence_direction`) or by a key function (`rank_by`), ties going to the lowest id. The medoid is `agreement.medoid`, the one rule of both modules (#135): the pose with the smallest mean distance to the others among the poses whose row has no undefined distance; when no pose has a complete row, the mean runs over each pose's defined distances and the result carries a `caveat` (`representatives["caveats"]`).
- `binding_metrics.poses.descriptors`: descriptors of where a pose sits against a reference, for a pose already in the frame of the reference (`place_in_reference_frame`) and its `FrameResult`. `residue_set_descriptors(atoms, frame, reference, binder_chain=, target_chain=)` returns, for each named residue set of the reference, the number of set residues the pose has (`n_set_mapped`), the interface size (`n_interface`), the overlap of the interface with the set (`n_overlap`, `covered_fraction`, `interface_in_set_fraction`, `jaccard`) and the receptor area buried on the set (`receptor_buried_area_in_set_angstrom2`, `receptor_buried_area_in_set_fraction`). A residue is in the interface when its buried area is at least `interface_threshold_angstrom2` (default 0.5, the threshold of `compute_interface_metrics`). A set with more than `max_unmapped_fraction` (default 0.5) of its residues missing from the pose has every column `None` and a `reason` such as `22 set residues, 14 not in the pose`. Residues are identified by chain, number and insertion code, so 52 and 52A are two residues.
- `partner_descriptors(atoms, frame, reference, binder_chain=, target_chain=)` compares the pose's binder with each named partner of the reference (a known binder already placed on the reference receptor): `min_distance_angstrom`, `clash_atoms` and `clash_pairs` per cutoff in `clash_cutoffs_angstrom` (default 2.2 and 3.0 A, keys `"2.2"` and `"3.0"`), `shell_fraction` (binder atoms within `shell_angstrom`, default 4.0 A, of the partner), the receptor area that the pose and the partner both bury (`shared_buried_area_angstrom2`, `partner_buried_area_angstrom2`, `pose_buried_area_angstrom2`, `shared_fraction_of_partner`; summed over the receptor atoms that the pose and the reference have in common) and `overlap_volume_angstrom3`, the sum over atom pairs closer than the sum of their van der Waals radii of the volume that the two spheres share (`sphere_overlap_volume`). 1YCR with the crystal peptide as the partner and the peptide moved away from MDM2 by 0, 3, 6 and 10 A: shared area 662.3, 372.5, 111.4, 0.0 A^2.
- `interface_residue_table(atoms, frame, reference, binder_chain=, target_chain=)` returns the interface residue by residue in a long format with fixed columns (`chain`, `role`, `number`, `icode`, `name`, `binder_index`, `reference_chain`, `reference_number`, `reference_icode`, `buried_area_angstrom2`, `polar_area_angstrom2`, `apolar_area_angstrom2`, `solvation_dg_kcal_mol`, `in_interface`, `in_sets`): every binder residue (zero area allowed) and every receptor residue with buried area above zero, sorted by role, chain, number and insertion code. The area columns are the `per_residue` values of `compute_interface_metrics` computed with threshold 0, labelled additionally with the reference numbering. `interface_areas` measures a pose once and the three functions take its result as `areas`.
- `binding_metrics.poses.reconcile`, cross-model reconciliation on plain dictionaries (numpy, no pandas, no scipy; a value that cannot be computed is None with a reason, never NaN):
  - `gap_between_backends(aggregates, backend_a, backend_b, *, keys=None, scale="pooled")`: per aggregated key, `gap = mean_a - mean_b` (the sign follows the call) and `standardised_gap = gap / s_pooled`, with the standard deviation pooled over the seeds of the two back-ends (ddof = 1 inside each; needs two values per back-end and a pooled value above 0). `scale` also takes a mapping `{key: scale}` of positive numbers, for a spread taken over constructs instead of seeds. It reads the output of `aggregate_poses`.
  - `consensus_interface(rows, backend, min_fraction=0.5)` and `compare_consensus_interfaces(consensus_a, consensus_b, *, limit=None)`: the receptor residues (as `ResidueKey`, in the numbering of the reference) and binder positions that at least `min_fraction` of a back-end's valid poses hold in the interface, read from the `residue_table` of the rows; the Jaccard index of two back-ends' consensus sets (both sides, binder only, receptor only), the residues only one of them has, and with `limit` a `below_limit` boolean next to the value.
  - `rank_agreement(table, backend_a, backend_b, metrics=None, method="spearman")`: Spearman's rho (midranks for ties) or Kendall's tau-b of a metric between two back-ends over a population of constructs, with `n`, the number of constructs dropped for a missing value, and a reason when fewer than 3 constructs remain or one back-end's values all tie. Both agree with `scipy.stats` to 1e-15 on seeded data with ties (checked in the tests when scipy is installed; the library does not import it).
  - `hotspot_consistency(sensitivities, residue_table, top_m=3)`: from an alanine scan `{binder position: sensitivity}` (larger = more important) and the per-residue interface table of one pose, Spearman's rho between buried area and sensitivity and the fraction of the `top_m` most sensitive positions that are in the interface. Ties at the cut all enter the top set.
- `binding_metrics.poses.score_pose_set(poses, binder_chain=None, target_chain=None, metrics=(), reference=None, *, options=None, aggregate=..., group_by=("backend",), representative="medoid", heavy="representative", metric_kwargs=None, preflight="error", on_error="record", n_workers=1, tmp_dir=None, keep_tmp=False, residue_table=False, include_transform=True, construct=None, residue_maps=None, start_method="spawn")` scores the poses of one construct and returns a `PoseSetResult`, one JSON-ready nested dictionary (`schema_version` 1). Each pose is placed on the receptor of a `Reference` (without one, the pose with the lowest id that can be read plays that role), measured with the registry metrics that were asked for (computed on the transformed structure through a temporary mmCIF file, one per pose; `FrameOptions.metrics_frame="original"` reads the pose's own file), compared with every other pose (peptide RMSD for the alpha carbons, the backbone and every heavy atom, with and without refitting the peptide; statistics inside and between the groups of poses; complete-linkage clusters; medoids; interface and contact-map Jaccard overlap; positional spread), summarised per group (the back-end by default) with `n_ok` next to `n_total`, and given one representative pose per group and overall. The row of a pose holds `id`, `kind`, `content_hash`, `provenance`, `native`, `status` (`ok`, `partial`, `failed`), `reason`, `reasons`, `independent_of_design`, `profile`, `frame`, one block per requested metric exactly as the registry function returned it, and `descriptors` and `residue_table` when asked. A pose that cannot be read, has no binder or target chain, or cannot be placed on the reference (too few paired receptor residues, sequence identity below the limit) is a failed row with its reason and counts in `n_total`; a metric that raises or reports a `reason` gives a partial row and its sentence in `reasons`. `on_error="raise"` raises `PoseScoringError` at the first pose that failed. Metrics with `cost_class` `static` or `model` run on every pose, the others (and a metric with no declared class) on the representatives only (`heavy="representative"`, also `"all"` and `"skip"`). Arguments are checked before any pose is read, the pre-flight check of the requested metrics runs on the first readable pose (`preflight="error"`, `"skip"`, `"warn"`, `"off"`), `n_workers` scores the poses in worker processes (started with `start_method`, `"spawn"` by default, also `"forkserver"`, `"fork"` or None for the platform default, checked before any pose is read and recorded in `provenance["run"]`; a pool that cannot start gives a logged warning and the poses are scored one after the other; #134, #140), and the result does not depend on the order of the poses or on `n_workers`. Options are `PoseSetOptions(frame, agreement, aggregation, representative, descriptors)`; the result echoes the resolved values. `PoseSetResult` is a `dict` with `to_dict()`, `to_json(include_timing=True)`, `from_dict()` (it refuses a `schema_version` it does not know), `row(id)`, `summary()` (Markdown) and `to_flat_rows()` (one row of scalar columns per pose). [`docs/pose_sets.md`](docs/pose_sets.md) describes the layer and its result.
- `binding_metrics.poses.write_pose_report(result, fmt="json", path=None, *, include_timing=True, max_list_items=16)` writes a pose-set result as `json` (the canonical dictionary, NaN tokens kept, `nonfinite_fields` listing them), `csv` (scalar columns only: nested keys joined with `.`, a short list of scalars as `name[0]`, `name[1]`, longer lists and the residue table left to the JSON), `md` (a table per group of poses, the failed poses with their reasons, the agreement block, the aggregates, the representatives, the warnings) or `html` (the same content as one page with inline styles, no script and nothing fetched from a network). The output depends on the result only.
- With several references, `score_pose_set(reference={"strict": Reference(...), "loose": Reference(...)})` places each pose once per reference variant (the first variant defines the frame of the metrics and of the agreement) and writes `frame["variants"]`; a variant with residue sets or partners adds `descriptors[variant] = {"sets": ..., "partners": ...}` (the descriptors of `binding_metrics.poses.descriptors` in the frame of that variant, thresholds in `DescriptorOptions`), and `residue_table=True` adds the per-residue interface table to each row. The names of `binding_metrics.poses` now include the pose kinds, `Reference`, `Partner`, `ResidueKey`, the frame, aggregation, descriptor and reconciliation functions of the pose modules, `score_pose_set`, `PoseSetResult`, the option classes, `PoseScoringError` and `write_pose_report`; they load on first access.
- A medoid chosen when no pose has a complete distance row (an undefined pair from `exclude_closure_mismatch` or `min_shared_atom_fraction`) is reported with a caveat in `result["warnings"]`, `result["agreement"]["medoids"]` and `result["representatives"]["caveats"]` (#135).
- `binding_metrics.testing.make_synthetic_poses`: a deterministic pose set (default 3 seeds x 2 back-ends) from the bundled 1YCR complex by rigid-body motions of the peptide, with the pairwise Calpha, backbone and heavy-atom RMSD after receptor superposition in closed form (agreement with the computed value better than 1e-4 angstrom; observed about 1e-6). - Tests pin the layout of a pose-set result as a committed list of keys per block (a removed or renamed key points to `schema_version`, an added key to the list), and check that the static pose-set path (the imports, a call with the static metrics, a reference and the writers) runs with `openmm`, `simtk`, `mdtraj` and `pdbfixer` hidden and never looks for them (`tests/test_pose_f2_imports.py`).
- **`ins_code` in the `per_residue` entries of `compute_interface_metrics` (#117).** Each entry has an `ins_code` key (the insertion code, an empty string when the residue has none), and the `residue` label, which also fills `interface_residues_peptide` and `interface_residues_receptor`, appends the code to the number when there is one: `ALA:A:52A`. Residues were already grouped by (chain, number, insertion code), so 52 and 52A were two entries, but both read `ALA:A:52` with `res_id` 52. The per-residue table of the Markdown report labels and sorts by number and insertion code.

- What the text says about the OpenFold3 modes. `score` was described as giving OpenFold3 both chains as templates so that it evaluates the known conformation, and an OpenFold3 adversary in score mode as agreeing with the design partly by construction. A template carries the fold of one chain and no inter-chain geometry: each query chain gets its own template structures, so no cross-chain geometry is ever supplied, and the template embedder of OpenFold3 v0.5.0 applies the same-chain mask to the validity indicators of the template pair features. So `score` gives each chain its own structure and OpenFold3 places the binder itself: its confidences refer to its own pose, and `binder_ca_rmsd` and `delta_com_angstrom` say how far it is from the input pose. The docstrings, the help of `--openfold-mode` (`binding-metrics-run` and `-batch`), the `binding-metrics-openfold` help, `README.md` and `docs/metrics.md` say so, and `docs/metrics.md` records the known limitation that the ColabFold MSA server can replace the template alignment of a chain for which it finds hits (#68, open). Read from the OpenFold3 source, not run.
- **`PredictionRecord` is renamed `PredictedPose`.** The class keeps every field, method and rule; it now inherits from `Pose`. Code, tests and documentation use the new name, and the old one still imports (see Deprecated). - **The static pose-set path imports no simulation package (#138).** A `score_pose_set` call with the static metrics no longer imports `openmm` or `mdtraj` when they are installed (OpenMM takes about a second and registers its plugins); with `openmm`, `simtk`, `mdtraj` and `pdbfixer` hidden it does not even look for them. `provenance.openmm_version` is now read from the metadata of the installed OpenMM distribution instead of from the imported library: 8.2 -> 8.2.0 for the conda 8.2 build, and None when OpenMM is not installed, as before. `binding_metrics.metrics.sasa` imports mdtraj inside `calculate_buried_sasa` and `calculate_interface_sasa`, so its module-level name `md` is gone; the `ImportError` message for a missing mdtraj is unchanged.
- `--prediction-lock-threshold` is accepted with `--prediction-mode refold-lock` as well as `score-lock`. With another mode the usage error (and the `ValueError` of `run_pipeline` and `run_batch`) reads "--prediction-lock-threshold is the threshold of the mode score-lock or refold-lock, and the run is in mode X; add --prediction-mode score-lock or --prediction-mode refold-lock". `--predictor boltz2 --prediction-mode refold-lock`, which was refused as a mode the runner does not run, runs the model.
